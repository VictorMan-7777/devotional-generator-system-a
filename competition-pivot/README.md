# competition-pivot/

All documents, tracking, and auditing for DevG's competition pivot live here.
This directory is isolated from training outputs and system docs to keep the pivot
work auditable without interference.

## Contents

| File | Purpose |
|---|---|
| `hebrews-passing-baseline.md` | Team-defined criteria for what constitutes a passing Hebrews 1-10 devotional. Used as pre-competition Gate for System B verification and as DevG's internal readiness standard. |
| `implementation-plan.md` | Staged plan for getting DevG to competition submission. Includes what changes, what does not change (long-term architecture preserved), and stage-gate validation criteria. |
| `stage-gate-tracker.md` | Current stage, status of each validation gate, and blockers. Updated as stages are cleared. |
| `audit-log.md` | Decision log — what was decided, when, by whom, and why. Permanent record. |
| `system-b-test-results/` | System B Hebrews test output and scoring when it runs. |

## Ground Rules

1. Changes for competition readiness must not break the long-term training architecture.
   Additions are allowed. Destruction is not.
2. Every stage transition requires a validated gate — documented here before work proceeds.
3. The Hebrews baseline is the shared standard for both systems. It was team-defined
   and Competition Director-validated before use.
